# Fitness Facility Occupancy Prediction and Service Recommendation System

ระบบเว็บพยากรณ์ความหนาแน่นของฟิตเนสและแนะนำบริการ ช่วยให้ผู้ใช้เลือกฟิตเนสและช่วงเวลาที่คนไม่แน่น ดูตำแหน่ง/ระยะทาง อุปกรณ์ และรีวิว ส่วนผู้ประกอบการดูภาพรวมความหนาแน่น ผลวิเคราะห์รีวิว และติดตามการแก้ไขปัญหาได้

> **หมายเหตุสำคัญ:** ข้อมูลความหนาแน่น ความจุ เวลาเปิด-ปิด อุปกรณ์ และรีวิวในโปรเจกต์นี้เป็น **ข้อมูลจำลอง** ที่สร้างจากกฎที่ออกแบบเองเพื่อสาธิตแนวคิด ไม่ใช่ข้อมูลเช็กอินจริงของฟิตเนสใดๆ ชื่อฟิตเนสใช้เป็นตัวอย่างประกอบเท่านั้น ตัวเลขความแม่นยำของโมเดลจึงบอกได้เพียงว่าขั้นตอนทั้งระบบทำงานถูกต้อง ไม่ได้เป็นการรับรองความแม่นยำกับสถานการณ์จริง

## ฟีเจอร์

**ผู้ใช้ทั่วไป**
- ดูรายการฟิตเนส แผนที่ และระยะทางจากตำแหน่งของผู้ใช้
- ดูความหนาแน่นปัจจุบัน (น้อย / ปานกลาง / มาก) และพยากรณ์รายชั่วโมงตามวันที่เลือก
- รับคำแนะนำฟิตเนสและช่วงเวลาที่เหมาะสม โดยพิจารณาระยะทาง ความหนาแน่นที่พยากรณ์ คะแนนรีวิว และอุปกรณ์ที่ต้องการ
- เขียนรีวิวและให้คะแนน ระบบวิเคราะห์ความรู้สึก (Sentiment) และจัดกลุ่มประเด็น เช่น อุปกรณ์ ความสะอาด แอร์ พนักงาน
- ยืนยันผลเมื่อผู้ประกอบการแจ้งว่าแก้ปัญหาแล้ว

**ผู้ประกอบการ**
- Dashboard ช่วงเวลาที่แน่น สรุปความรู้สึกและประเด็นจากรีวิว
- ติดตามสถานะปัญหาที่ผู้ใช้แจ้ง

## ข้อมูลจำลอง

สร้างโดย `gen_occupancy_data.py` จำนวนคนในแต่ละชั่วโมงคำนวณจาก

```
count ≈ Poisson( ความจุ × peak_util × shape(ชั่วโมง) × day_mult ) + Normal(0, 4% ของความจุ)
```

- `shape(ชั่วโมง)` คือรูปแบบพีคของยิม (กราฟระฆังหลายลูกรวมกัน) แยกวันธรรมดา/วันหยุดสุดสัปดาห์
- `day_mult` คือตัวคูณระดับวัน: วันในสัปดาห์, วันหยุดนักขัตฤกษ์, ช่วงปิดเทอม/สอบ (เฉพาะยิมในมหาวิทยาลัย) และเหตุการณ์ผิดปกติแบบสุ่ม
- ใช้ random seed คงที่ รันซ้ำได้ข้อมูลเดิม ข้อมูลย้อนหลัง 120 วัน ประมาณ 9,700 แถว

ฟิตเนสตัวอย่างแต่ละแห่งมีบุคลิกต่างกัน (ความจุ เวลาเปิด ชั่วโมงพีค): The Boys Gym Club, Mega Gym, Infinity Gym, Bon Fitness (ในมหาวิทยาลัยขอนแก่น), NP Park

เกณฑ์ระดับความหนาแน่น (จำนวนคน ÷ ความจุ)

| ระดับ | เงื่อนไข |
|---|---|
| low (น้อย) | < 35% |
| medium (ปานกลาง) | 35% – 65% |
| high (มาก) | ≥ 65% |

## โมเดลพยากรณ์

- **เป้าหมาย:** จำนวนคนในยิมรายชั่วโมง
- **ฟีเจอร์:** ยิม (one-hot), ชั่วโมง, วันในสัปดาห์, เป็นวันหยุดสุดสัปดาห์, เป็นวันหยุดนักขัตฤกษ์, อยู่ในช่วงสอบ
- **การแบ่งข้อมูล:** แบ่งตามเวลา ใช้ 14 วันสุดท้ายเป็นชุดทดสอบ (ไม่สุ่มปน เพราะงานจริงคือทำนายอนาคตจากอดีต)
- **ตัวชี้วัด:** MAE และ RMSE (หน่วยเป็นจำนวนคน)
- **ผลเบื้องต้น:** โมเดลแบบต้นไม้ (Random Forest, XGBoost) คลาดเคลื่อนน้อยกว่า Linear Regression อย่างชัดเจน เพราะความหนาแน่นรายชั่วโมงเป็นรูปพีคที่ไม่เป็นเส้นตรง ตัวเลขล่าสุดดูที่ `results/model_comparison.csv` หลังรัน `ml/train_models.py`

## เริ่มต้นใช้งาน

ต้องใช้ Python 3.11 หรือ 3.12 (เวอร์ชันที่ใหม่มากอาจยังไม่มีไฟล์ติดตั้งสำเร็จรูปของบางไลบรารี)

```bash
# 1) สร้างและเปิดใช้ virtual environment
python -m venv .venv
# Windows (PowerShell):  .\.venv\Scripts\Activate.ps1
# macOS/Linux:           source .venv/bin/activate

# 2) ติดตั้งไลบรารี
pip install -r requirements.txt

# 3) สร้างข้อมูลจำลอง -> data/gyms.csv, data/occupancy.csv
python gen_occupancy_data.py

# 4) ฝึกและเทียบโมเดล -> results/model_comparison.csv, models/best_model.joblib
python ml/train_models.py

# 5) ทดสอบฟังก์ชันพยากรณ์ และสร้างกราฟ
python ml/forecast.py
python ml/plot_hourly.py


# 6) ฝึกโมเดลวิเคราะห์รีวิว -> models/sentiment.joblib
python ml/sentiment.py

# 7) สร้างฐานข้อมูล + รีวิวจำลองรายฟิตเนส -> gym.db
python -m app.import_data
python gen_gym_reviews.py
python seed_reviews.py

# 8) เปิดระบบ (เว็บ + API + Dashboard)
uvicorn app.run_all:app --reload
# เปิดเบราว์เซอร์ที่ http://127.0.0.1:8000
```

ลำดับสำคัญ: ถ้าแก้ค่าใน `gen_occupancy_data.py` (ความจุ เวลาเปิด ปฏิทิน) ให้รันข้อ 3 และ 4 ใหม่ทุกครั้ง

## API

รูปแบบ endpoint และ response ทั้งหมดอยู่ใน [API.md](API.md) สรุปสั้นๆ

| Endpoint | หน้าที่ | ผู้รับผิดชอบ |
|---|---|---|
| `GET /gyms` | รายการฟิตเนส ความหนาแน่นปัจจุบัน ระยะทาง | B |
| `GET /gyms/{id}/forecast?date=` | พยากรณ์รายชั่วโมง | A |
| `POST /recommend` | จัดอันดับฟิตเนสและช่วงเวลาที่แนะนำ | A |
| `GET/POST /gyms/{id}/reviews` | รีวิว พร้อมผล Sentiment และประเด็น | B (เรียกโมดูลของ A) |
| `GET /owner/dashboard` | สรุปสำหรับผู้ประกอบการ | B (ข้อมูลจาก A) |
